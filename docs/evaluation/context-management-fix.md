# 上下文管理修复与复测（2026-11-01）

## 确认的问题

1. 评测的 `_RoleScopedProvider` 把摘要 `max_tokens` 压到主 Agent 的
   `generation.max_tokens=500`。之前 5 个跨轮次任务的摘要全部返回 length、空正文。
   这是评测接线错误，不是“真实模型已经给出了完整摘要但忘记约束”。
2. `CodeFlowHistorySegmentBuilder` 先执行 summary boundary / recent tail，再保护
   新列表第一条消息。原始首轮约束此前已经被排除，保护不到它。
3. 确定性摘要只取最近 12 条事实，早期用户约束和先前摘要优先级低，失败后会遗忘。
4. 非空但被截断的摘要也会被接受；持久化 boundary 只有消息数量，没有源前缀校验。

## 修改

- 增加独立配置 `context.compact_max_output_tokens`，默认 2048；
  `context.compact_timeout_seconds` 默认 30 秒。评测为 shipping history policy
  单独传递摘要输出上限，主 Agent 仍为 500 Token，其余 Curator 对照路径保持原上限。
- 在原始 append-only 历史上确定最早 `protect_first_n` 个用户消息，跨 summary
  boundary 和 tier2 tail pruning 保留，保持原始 user role 与完整文本，不依靠摘要重建。
- fallback 先保存初始用户要求和既有摘要，再加入最近事实；保留完整原始会话。
- 拒绝 finish_reason=length/error、空或过长的摘要，超时也降级；metadata 保存
  `summary_failure_reason`。不把错误文本作为成功摘要。
- 绑定被压缩历史前缀的 SHA-256；同 session 的历史替换或截断后不复用旧 boundary。

原始消息保护有配置数量上限，不等于自动识别并永久保留任意轮次的所有业务约束。
它也不能保证模型不会额外输出字段，任务正确性仍交给独立 verifier。
