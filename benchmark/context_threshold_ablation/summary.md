# Context Threshold Ablation：阶段性结果

## 状态

**正式实验未完成，不得据此选定阈值。** 当前文件包含 3 条真实预实验记录，以及 12 条正式阶段中断前已持久化的真实 trial 记录（共 15 行）；完整设计是 12 个任务 × 3 次重复 × 3 个阈值 = 108 条正式记录。正式记录只覆盖 `ctx-incident-handoff` 和 `ctx-release-brief` 的部分重复，没有覆盖全部任务集。

实验在第一个运行版本中将 Provider 请求估算输入上限设为 16,384。序列化后的部分模型请求超过此上限，被实验预算守卫以 `task_budget_exhausted` 阻止；运行产生大量不完整的任务超时。虽然这些拒绝请求没有越过费用硬上限，但失败机制污染了时延和任务质量比较。之后我将上限改为 42,000、关闭重试以符合 ¥40.32 的最坏情况预算，再次启动的真实矩阵被自动审批拒绝（理由：私有仓库代码、工具输出和任务数据将发送给 DeepSeek）。因此没有擅自重试或改用绕过路径。

## 成本、异常与可复现性

- 模型：配置中的 `deepseek/deepseek-v4-flash`；Provider 返回的模型标识记录为 `deepseek-flash`。
- 窗口：8,192；输出预留：500；ContextAssembler 工作预算比例固定为 0.80；温度为 0。
- 三组只改变 `structured_compact_threshold`；Context 压力输入由确定性填充器生成。
- 价格估算：输入 $0.14/百万 Token、输出 $0.28/百万 Token、美元兑人民币 7.5；未计供应商缓存折扣。费用 estimate 不等同账单。
- 首轮执行策略为每 Provider 请求最多 2 次尝试、输入估算上限 16,384；修正后的脚本采用每请求 1 次尝试、上限 42,000。两种配置没有混作同一个有效实验结果。
- 运行账本摘要、试验 journal、Manifest 和逐 Trial JSON 均保留在 `.codeflow/e/2189b500/`；CSV 每行包含来源记录路径。预实验报告还在同目录 `d374.../REPORT.md` 与 `summary.json`。
- 自动审批拒绝了重跑，当前没有完整矩阵，没有有效的 50/80/93 阈值胜负结论。
